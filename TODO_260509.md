# Codomon — Architecture Hypothesis UX/UI Improvements

## Goal

Improve the Architecture Hypothesis synthesis experience so the user can:

- understand what the system is doing
- estimate remaining time
- detect stalled/rambling LLM generations
- recover gracefully from token-limit failures
- trust the synthesis process

The current experience feels opaque during long LLM calls.

---

# 1. Add Real Run Telemetry Panel

## Problem

The user currently cannot tell:

- whether the LLM is progressing
- whether the model is looping/rambling
- whether generation speed dropped
- whether the batch is healthy
- how long remains

---

## Add Top Status Card

Place above the log view.

Example:

```text
Architecture Synthesis Running

Batch 11 / 20
Processed 760 / 1420 summaries
Elapsed: 08m 12s
ETA: ~06m 48s

Prompt Tokens: 25,767
Generated Tokens: 18,442
Generation Speed: 46 tok/sec
Average Batch Time: 42 sec
```

---

# 2. Add Live Generation Streaming View

## Problem

Currently the user cannot see generated content while the LLM is running.

This makes it impossible to detect:

* looping
* repeated JSON
* rambling prose
* malformed responses
* stuck generations

---

## Required Feature

Add a collapsible panel:

```text
Live LLM Output
```

The panel should stream tokens/content as they arrive from llama.cpp.

Example:

```json
{
  "systems": [
    {
      "name": "UI",
      "modules": [
```

---

## UX Requirements

### The stream must:

* autoscroll
* support pause autoscroll
* support copy text
* show token count live
* show streamed character count live

---

## Add Warning Detection

Detect suspicious patterns:

### Repetition detection

Example:

```text
Warning: repetitive output detected
```

Triggers:

* repeated JSON blocks
* repeated paragraphs
* same line repeated N times

---

## Add Long Generation Warning

Example:

```text
Generation unusually long for this batch
Expected: ~45 sec
Current: 8m 22s
```

# 4. Add Token Budget Preflight Check

## Problem

The system currently sends prompts that are too large.

Example failure:

```text
Prompt: 25,767 tokens
Generated: 39,769 tokens
Total: 65,223 / 65,535
finish_reason=length
```

This wastes 10–15 minutes before failure.

---

## Required Behavior

Before sending a batch:

Estimate:

* prompt token count
* remaining context budget
* expected output size

---

## Add Safety Rules

Example:

```text
If promptTokens > 45% of context:
    split batch automatically
```

---

## Add UI Warning

Example:

```text
Batch is approaching model context limits.
Automatic split recommended.
```

---

# 5. Add Automatic Split-and-Retry

## Problem

A single oversized batch currently fails the entire synthesis.

---

## Required Behavior

When:

```text
finish_reason=length
```

Automatically:

* split batch into smaller groups
* retry automatically

Example:

```text
Batch 11 exceeded token budget.
Retrying as:
- 11A
- 11B
```

---

## UX

Show retry progress clearly.

Example:

```text
Batch 11A running...
```
